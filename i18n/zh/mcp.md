# 连接 Agent 与 NERV

[English](../../guides/mcp.md) · [NERV](README.md)

0.9.1 候选版通过本地 stdio MCP 桥接器连接已经运行的 Host。桥接器使用配对凭据，仅允许访问指定项目，不另起 Host、不连接电机、不安装资源，也不读取模型密钥。

## 配对客户端

1. 启动要使用的 NERV 渠道并创建 Project。公开安装器不会安装尚未发布的候选版；需要先通过开发流程取得候选包。
2. 打开“设置 → Agent 连接”，填写客户端名称，选择项目和仅观测／控制请求权限。
3. 创建连接，复制客户端 ID。NERV 在当前渠道中私密保存桥接凭据。可选的一次性 token 显示供需要它的接入程序使用；不要把 token 写进源码、Issue 或共享 MCP 配置。
4. 在客户端的 stdio MCP 配置中使用命令 `nerv` 和以下参数：

```json
{
  "command": "nerv",
  "args": ["mcp", "--channel", "preview", "--brain", "BRAIN_ID", "--client", "CLIENT_ID"]
}
```

将 `CLIENT_ID` 替换为配对 ID。只有正式 Host 已包含这些接口时，才使用 `stable`。这段 JSON 是启动器对象，外围配置格式由客户端决定。如果桌面客户端找不到 `nerv`，填写已安装启动器的绝对路径；不要在命令行中传 token。

对应的终端命令是：

```bash
nerv mcp --channel preview --brain BRAIN_ID --client CLIENT_ID
```

该进程等待 stdio 中的 MCP 协议消息，不提供聊天终端。错误输出到 stderr。NERV 重启后，需要重新连接桥接器，读取当前项目与任务状态，获得新观测后再继续。

## 明确交付控制权

配对与动作授权是两件事。先在 NERV 启动世界或设备工作区，选择兼容方案；真机由操作者完成准备，再按需授权动作。打开人工控制工具，选择已配对 Agent，并点击“接受 Agent 请求”。同一时刻只有一个 Agent 持有运动控制权。

“人工接管”先撤销外部运动权限，再请求停止。停止失败时，控制保持禁用，不代表机器人已经停下。交还控制权需要明确选择 Agent。“暂停 Agent 请求”阻止新请求，不表示当前执行已经结束；停止任务和紧急停止仍是独立操作。

可以在设置中撤销配对。撤销、进程重启或任务取消后，都不应重放旧动作请求。

## 持续读取并确认观测

下列是当前导出的工具名称，不是任意命令执行入口：

| 工具 | 用途 |
|---|---|
| `projects_list`、`project_get`、`capabilities` | 查看允许访问的项目、当前运行与声明的动作 |
| `run_start`、`run_end` | 启动或结束自己持有的仿真运行，不连接真机 |
| `observe`、`acknowledge` | 获取允许的传感器图像，并确认本次观测回执 |
| `task_start`、`task_status`、`task_update`、`task_cancel` | 使用稳定任务标识并读取实际状态 |
| `action` | 在外部任务内请求一个允许的动作 |
| `events`、`activity` | 读取有上限的事件，或发布带来源的简短说明 |

`task_start` 与 `action` 还接受可选 `receipt_id`。显式传入表示调用者已经处理过该回执对应的原图；Brain 在同一请求中核验回执并准入，避免分开的“确认—模型思考—动作”耗用大部分运动监督期限。服务器不获取替代图像、不确认未读帧、不刷新采集时刻，也不增加 Runtime 期限。每次动作都使用新的、实际处理过的回执；已单独确认或被 `task_start` 使用的回执不能再次确认。幂等重试直接返回原结果，不重新确认或执行。

`brain_get.world_health` 返回共享 World 最近的健康分类。探测不可用时禁止运动并撤销当前控制租约，不据此直接结束尚未确认故障的 Run。同一实例恢复正常后，须取得新观测并重新申请控制；任务和动作不自动恢复。确认的进程或 epoch 故障仍使旧连接失效。图像准备纳入 World 就绪过程，诊断帧不会替客户端确认观测。

动作执行期间拒绝新的确认，后续观测不能延长旧动作捕获的期限。取消不等待该实例的确认／准入锁；命令终结未确认时，继续封锁确认和任务启动，直至停止与执行终结均有检查。中断回执区分执行未知和物理停止确认，不再将所有中断称为操作者停止。

取消后，Runtime 可能进入受监督保持，而连接仍持有原控制权。`task_start` 在保持或就绪状态不明时拒绝请求，不消费回执、不创建任务。已有控制者再次调用 `control_acquire` 会收到 `runtime_held` 和 `reacquisition_required`，不能据此视为运动就绪。在已有操作者预授权范围内，显式调用 `control_release`，检查新观测，再调用 `control_acquire` 建立新的控制代次；开始新任务前再检查一次新观测。恢复要求停止已确认，不继续旧动作。保持期间的动作拒绝报告 `executed=false`，有实测依据时附带 `hold_reason`；保持本身不能证明发生了操作者急停。

先读取项目与能力，再请求观测。检查所需图像与元数据后确认回执。确认记录的是客户端的声明，不证明模型理解了画面。任务启动和动作请求需要新鲜且已确认的观测、当前实例及控制权代次，并使用操作者选定的方案。

`run_start` 将执行记录附着到已有资源，不能创建机器人、启动／重启 World 或重建场景。操作者先启动 World，再通过发现入口的实例授权允许 Agent 申请机器人。已配置但尚未启动的 World 会拒绝申请，且不消耗机器人配额。分配完成后附着返回的 Brain，读取当前状态并启动 Run；结束 Run 保留 World 中的机器人。

G1 仿真观测在 `state.image_frames[sensor]` 中保留返回 PNG 的相机源序号 `source_sequence`、实际采集仿真时间 `captured_sim_time`、采集墙钟时间、World 代次、Robot／World 身份、拓扑修订及 `image_sha256`。它们对应图像采集，不是较早的机器人状态读取或较晚的交付时刻。确认仍使用 Runtime 的 `frame_seq` 和观测回执；相机源序号不代表已确认。旧传感器缺少采集元数据时明确标记不可用，不补造采集时间。

修改请求需要调用方生成 `request_id`。只有重试完全相同的请求才复用 ID；参数改变时使用新 ID。动作还需当前任务 ID 和版本。有限动作结束后，先重新观察，再发下一个动作。固定 ACT 不依赖模型响应速度，但仍需要按声明的期限持续监督。

G1 观测还提供本机传感器契约。`state.proprioception` 包含具名关节的位置与速度、机体坐标系角速度和 IMU 比力（包含重力），分别标明有效性与采样时间。缺失或尚未采样的数据返回不可用，不填零。`heading_deg` 相对于 Runtime 初始航向；仅在 `heading_reference.valid` 为真且 `frame_id` 未变时使用。重置会使旧参考失效。

`clearance_m` 和 `front_cone_m` 是单高度点射线；射线距离较远不代表机器人全身能够通过。`motion_space.forward` 与 `.turn` 提供现有全身制动预检的独立采样时间、本机包络、距离和禁止原因。这是机体局部测量，不是地图、到达判定或运动授权；执行时仍重新检查。停止或制动回执中的实际前进、侧向位移与转角，也不能证明任务目标已经完成。

图像帧的 `calibration` 可包含实际渲染分辨率、透视垂直视场角（度）或正交垂直跨度（米）、相机与基座轴约定，以及采集时的相机到本机基座变换。仅本机上的固定式相机提供该变换；跟踪式及外部相机明确返回标定不可用。关节运动会改变变换。模型内参数组标明单位与启用条件，不是像素内参矩阵。各传感器采样时间可能不同，不能把整份观测当作同一瞬间的图像与状态。接口不提供 World 位置、场景地图或目标坐标。

通过带有限 `wait_s` 的 `events` 或 `task_status` 查看进展，两者都不续期观测监督。模型延迟或断开时，本地监督期限仍然有效。不要为了保持任务运行而确认未看过的帧。除非有独立成功判据，工具返回执行结果不等于任务成功。

## 范围

本版仅支持同机连接。桥接器拒绝非本机 Host 地址，并检测 Host 实例变化。浏览器操作者接口与 Runtime 节点接口不是通用 Agent 接口。带认证的远程连接及独立外部 Agent 部署留待后续开发，见[部署图](../../assets/readme/diagrams/zh/deployments-091.svg)。


## 0.9.1 资源发现与 Brain 绑定

操作者在控制台创建空 World，再在 Agent 连接中授权模板、出生位置、配额及可选的控制权限。Agent 使用 `nerv mcp --channel preview --client CLIENT_ID` 进入未绑定入口，通过 `platform_describe`、`robot_allocate`、`operation_get`、`brain_attach`、`robot_remove` 发现和申请实例。重复申请必须复用相同请求 ID；结果未知时先查询，不能创建第二个申请来掩盖未知状态。

`brain_attach` 会通知工具清单改变并固定该连接的 Brain 范围。已有 Brain 仍可直接用 `--brain BRAIN_ID` 连接。绑定后提供 `brain_get`、`control_acquire` 和 `control_release`。先启动引用已分配 Robot 的 Run，获取观测，在预授权范围内申请控制，再取得并确认新观测，才可开始任务。申请控制不等于确认图像。`task_update` 继续返回退役响应。

Robot 与 Brain 跨 Run 保留。授权观察者可以并存，每台机器人只有一个运动控制者。重连只恢复读取，运动需要当前观测和已确认停止；心跳不会确认图像或延长旧动作期限。实例申请与移除属于未绑定资源入口，必须符合操作者 World policy；Agent 不能重置或停止整个世界。

旧的 Run 预留流程仍作为兼容路径。当前动态生命周期源码尚在验证，长期稳定保持、安装候选及独立会合验收尚未完成，见[开发说明](brain-core-091.md)。

实例申请与移除立即返回操作 ID；用 `operation_get` 轮询直至完成、失败或中断。同一身份和请求 ID 的重试返回已有操作。Host 重启不重放未完成申请；失败操作保留已分配身份供恢复检查。


申请控制后先检查 `ok`，再执行后续请求。申请被拒后，不继续调用 `acknowledge`、`task_start` 或 `action`；可取得新观测核对状态，不能确认未看过的图像，也不能重建任务绕过停止检查。绑定所有者可以在尚无运动权时请求结束自己的待命仿真 Run，但结果仍须实际停止确认。

操作者可通过 `POST /api/world-instances/{id}/agent-topology` 关闭后续 Agent 增删实例请求，提交 `allow_agent_changes: false` 和当前 `expected_topology_revision`。权限变更会等待正在执行的成员事务，并拒绝过期修订；现有机器人实体、观测和控制租约保持有效。这不是 Agent MCP 工具。正式会合试验在双方实例准备完成后关闭该权限。
