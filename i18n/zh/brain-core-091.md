## 职责边界

外部 Agent 负责目标理解、视觉判断、规划、模型调用和对话上下文。Brain Core 随 NERV 安装，负责身份绑定、观测回执、任务、授权和执行记录。Runtime 负责驱动、ACT／步态推理、高频控制与本地停止。Brain Core 不包含 AI Agent，也不独立安装。

当前实现位于 `nerv.brain_core`。历史 `nerv.brain`、`nerv.harness`、`nerv.vlm` 源码保留用于恢复，但 wheel 与 npm 包排除其实现。旧聊天、模型、模型密钥写接口返回退役响应；内部上下文压缩写入也已停用。历史记录可读，升级不调用模型、不搬运模型密钥。资源下载凭据另行管理。

## 持久资源与通信

每个 Project 仍对应一台受控机器人。World、Robot 与规范 Brain 独立于 Run 保存；操作者可先创建空世界并授予实例申请权限。未绑定 MCP 提供资源发现和幂等申请；绑定后的 `nerv mcp --channel CHANNEL --brain BRAIN_ID --client CLIENT_ID` 仅操作一个 Brain。`brain_get` 返回资源与控制状态；回执保留原始执行身份，不用新授权重标旧回执。

World 启动是明确的操作者资源操作。实例申请在消耗配额前拒绝未启动或不可用的 World，不隐式启动仿真。Run 要求已有 World 和 Runtime 就绪，场景、机器人配置与连接代次匹配；启动只发布执行记录及当前 World 成员中的 Run 引用，结束不销毁这些资源。通过 Run 重建 World 的旧入口退役，改用 World 生命周期操作。预留 Brain 在明确绑定前可以没有 World；旧独立 Run 保留历史，但不能恢复原来的隐式资源创建路径。

MCP 心跳只证明连接存活，不确认图像。授权观察者可以并存，但只有一个运动控制者；观察者断开不会撤销另一 Agent 的控制权。控制者重连恢复读取，在预授权范围内取得新观测后可重新申请控制，不重放动作。

Agent 可在 `task_start` 或 `action` 中显式提交已处理观测的 `receipt_id`，将该次确认与请求准入合并。回执仍一次性使用，保留原观测时效；这不是自动确认。每机器人准入锁在执行期间拒绝新确认，后续图像不能延长旧动作捕获的期限。传输／执行终结未知的屏障独立于物理停止；新 Task 从自己的状态开始，不继承上一 Task 的停止和执行结果。

World 健康监督区分确认正常、探测不可用或数据不完整、确认故障。健康未知时撤销运动权，并以准确的 Runtime 控制身份停止已登记的任务或人工执行，保留资源和 Run 身份。同一 epoch 恢复后允许重新读取，不恢复旧授权、不重放动作；进程退出、epoch 改变或节点明确报告故障仍终结受影响资源。携带准确控制身份的停止不依赖 World 健康探测。渲染上下文和首帧在初次就绪及拓扑更新发布前准备；诊断像素丢弃，不生成观测或确认。传感器准备失败与物理运行可用性分别记录。

## 动态共享 World

共享 World 使用同一 MuJoCo model/data、物理时钟和真实碰撞。成员事务协调停止、构建独立候选模型、按名称迁移状态并递增拓扑修订。各机器人拥有独立总线、Runtime、相机和执行记录。结束 Run 保留机器人；移除实体是单独操作。当前候选拒绝无法迁移的 activation、equality、mocap 和 plugin 状态，以及非空场景配置覆盖。

## 执行与资格

无模型执行服务支持外部原子动作、外部技能和固定策略。新建任务不能抹去同一实例的技能转换历史。Runtime 对 G1 转换另外核对场景及策略、契约、发布文件哈希。先前开发契约限定已有 G1 转向策略与 apt 仿真，不适用于 Go2、任意策略、ACT 技能转换或真机。

先前双 G1 并发开发探针共执行 14 次前进／转向动作，14 次确认稳定停止，未报告跌倒。其中六次 0.5 米请求的最终偏差为 0.003～0.021 米，八次 45 度转向偏差为 0.5～3.3 度。这是限定组合的开发证据，不是独立导航验收，也不代表广泛可靠性统计。未验证的 0.5 米以下前进请求在运动前拒绝。接近目标时使用已有策略支持范围内的速度减速，不补偿固定偏移。

动作回执分别报告实测位移、请求目标、目标偏差、受阻、跌倒、超时与停止确认。`travel_threshold_crossed` 表示局部控制阈值；`target_reached=null` 不声称到达目标。最终到达仍须独立评分。Agent 可以静止等待思考，但旧观测失效后必须重新检查图像，不能用心跳或轮询维持运动授权。G1 apt CPU 契约 `g1-apt-cpu-mcp-091-2` 将图像采集至显式确认的有效期设为 40 秒，运动监督期限独立保持 20 秒。两个独立 MCP Agent 的六次看图预检测得采集至确认耗时 11.08–19.96 秒；有效期按实测最大值两倍、向上取整至 5 秒确定，仅适用于 apt 仿真。安装候选已经执行固定导航与连接失联试验，结果见下文；协议检查通过不等于导航任务通过。

## 迁移与恢复

历史 managed／内部决策项目保留配置和日志，并要求重新选择外部控制方案；不会静默取得新控制权。固定策略保持执行路线。Project／Run／Task 继续是唯一事实记录。候选测试使用隔离数据目录；正式安装替换、公开发布与远程部署分别处理。

G1 普通动作结束后最多等待 4 个仿真秒，以满足原有的 0.3 rad/s、持续 0.2 秒安静标准；紧急保持的 1.5 秒期限不变。安装候选中的一次 30 度转向耗尽旧等待期限，保留的真值显示其返回约 0.09 秒后才开始出现合格安静区间。新期限按实测约 1.79 秒完整稳定时间的两倍向上取整确定，不改变速度命令、步态权重、安静阈值或 20 秒运动监督期限。停止仍未确认时继续拒绝下一次运动。这项校准本身不代表导航验收通过。


## 安装候选实际结果

本节保留较早候选的原始结果。“当时待验证”描述各自历史检查点，不替代篇首候选 25 的当前资格。

后续候选 8c88（源码 `ed9c787`）通过 837 项 CPU 检查及隔离安装／恢复，实际 Runtime 使用已测 NumPy 2.5.2。安装后的真实 MCP 工程链共完成十四次运动并确认停止，其中一台覆盖前进／左转／右转的全部九种有序组合；最后约 60 秒物理记录中，双方速度及漂移均满足原停止界限。结束 A 的 Run、随后移除 A 后，B 各自又完成了一次实测运动。这些定向工程检查不能代替独立会合验收。

该记录结束后，检查控制台时 B 的工程任务实际达到 900 秒期限。Runtime 与 Host 并发停止产生了历史未知任务回执，后续物理停止则有确认。因此开发版加入同 Runtime 代次内正在执行的停止结果共享：加入者在控制锁外最多等待 `NODE_TIMEOUT`，Host 停止传输另加正数 `NODE_STATUS_TIMEOUT` 作为响应余量。这只限制加入等待，不限制首条 provider 调用；超时不确认停止，不复用已完成停止的旧证据。旧任务计时器须在同一原子操作中核对 token 尚未置位且仍为当前令牌后才能撤销执行，因此也不能在替代任务解析控制方案时将它取消。原失败／未知回执保留；当时修复后的安装候选与全新独立试验尚未完成，不能追认该旧包通过。既有控制台的实例切换、相机及事件流已实际查看，样式与页面结构未变。

候选 66（`711668a`）通过 834 项 CPU 检查、两项退役 Provider 跳过，以及全新隔离安装／升级／回滚。首轮正式双 Agent 会合试验共发出四次运动请求：双方首个动作均完成并确认停止，随后切换到不同技能的请求均被拒绝，双方均未宣称成功。物理记录保留 4,359 个样本，实测约 25 Hz，无记录到的跌倒或机器人间碰撞；未形成共同会合稳定窗口。

根因是正式仿真安装按 `release/constraints/sim.txt` 使用 NumPy 2.5.4，而 G1 实测控制契约与开发验证锁要求 2.5.2。Runtime 正确拒绝了未经资格验证的组合。此前 Host 代码／配置核验及重复前进没有覆盖独立 Runtime 的数值依赖。构建现已检查 profile、验证输入／锁和安装约束的一致性，并拒绝版本不符的最终 wheel。控制契约未放宽；新包必须用 Runtime 自身解释器核验依赖，并完成全部有向技能转换，才能启动新的正式 Agent。这项打包修复不能追认候选 66，也不代表导航通过。

候选 08 基于 `248c7c0`，通过 713 项 CPU 软件检查，跳过两项退役 Provider 检查，并通过托管前端、隔离安装与恢复检查。两个独立 Codex subagent 通过各自真实 MCP 连接完成三轮并发导航：0/6 独立评分成功、3 次虚报到达、0 次跌倒、69 次运动请求。六项均未满足完整身体进入目标区；出生配置、目标几何和评分标准未调整。

已发现取消后的保持振荡、遇障制动后停止未确认，以及 World 故障后一次能力清单缓存为空、需要操作者刷新的问题。单 Run 生命周期检查中，A 结束后 B 仍有控制，但其 0.5 m 请求仅移动 0.024 m 后停滞。这些实测限制了前述开发探针的结论，该候选 08 当时不具备合格导航能力。

实际协议检查拒绝跨项目访问、跨实例观测回执和伪造代次字段。A 长轮询时 B 的取消约 0.027 秒完成；A 失联只撤销 A，重连保留原回执但不重放动作，也不自动恢复运动授权。共享 World 进程丢失使两个 Run 失败；单独结束 A 则保留两台物理机器人和 B 的运行。这些检查不能代替物理导航成功。旧试验记录与后续候选分别保存。

## 历史源码资格与保持诊断

当时的源码修订已将仿真站立控制与步态制动分开。Runtime 使用现有机器人模型、自身 IMU／关节／里程计和估计的局部平面支撑，计算有限时域的关节目标反馈；不读取场景模型或导航目标，不训练或替换步态网络。控制器在后台构建，运动命令及拓扑变化会使旧计算失效；动作须等到站立反馈实际接管并满足新的静止窗口后才返回完成停止，避免下一技能继承尚未结束的步态切换；构建错误明确报告并禁止后续运动。物理参数和基于传感器的停止阈值保持原值。

工程对照中，固定已学习的关节目标和上游固定站姿都出现跌倒，不能作为保持方案。机器人局部反馈随后通过 120 秒保持、前进／转向／恢复动作链及链后 900 秒保持，未记录到跌倒。最后一段长保持净位移约 5.3 毫米，最初三秒后的全部采样满足原静止判据。实际异步 Runtime 也完成两次一米前进及左右转向，并继续保持。这些属于源码级诊断，不是安装候选验收；有限时域计算不构成全局或无限期稳定保证，当时共享世界故障测试和固定独立验收仍需另立安装证据；当前候选 25 的后续结果见篇首。

部署时序复核发现，apt World 实际物理步长为 2 ms，而步态发布契约描述的是 5 ms。站立控制器现从执行连接读取实际步长，推导每个 50 Hz 命令对应的物理步数，不兼容的比例直接拒绝。按 2 ms 重新验证后，六种有序技能切换、双机器人并发前进、分别保持／恢复及 60 秒共同保持均完成；另一次动作链后的 900 秒保持净位移约 6.9 mm，最初三秒之后的 44,850 个采样点全部满足原有停止标准。这些仍是工程检查。技能切换资格同时绑定控制器代码、执行与运动配置、局部机器人模型及实际时序，不能只靠步态文件哈希沿用旧资格。

安装模块核验还发现源码与包的配置差异：名为 `body.yaml` 的模块配置实际使用 JSON，科学计数法数值被 YAML 解析器读成字符串，改变了冻结的控制配置哈希。注册表现先保留 JSON 的数值类型，再回退读取 YAML；回归将实际机器人配置序列化成模块格式，并核对加载后的数值契约。这修复配置一致性，不构成导航验收。

## 持续资源与会合完成修订

实例申请和移除先返回持久化操作 ID，再执行物理变更；通过 `operation_get` 查询 `complete`、`failed` 或 `interrupted`。失败保留已分配身份，重试不会重新生成实体。Host 重启将未完成操作标为中断；结果不明的物理变更须由操作者检查恢复。

本轮源码增加独立的 World、Robot、规范 Brain 存储，以及未绑定 MCP 的资源发现、幂等申请和附着入口。操作者先创建空世界，授权模板、配额、出生位置及控制权限。Agent 申请实体后才启动 Run；连接、观察者与运动控制权分别处理。绑定后新增 `control_acquire`、`control_release`，附着时通知 MCP 工具清单改变。旧的 Run 预留流程只作为兼容路径。

动态成员事务在 World policy 下协调停止，独立编译候选模型，按稳定名称迁移状态并重建映射；旧拓扑关节命令被拒绝。编译失败保留旧状态；提交后 Runtime 准备失败明确要求操作者恢复，不能描述成未发生变更。当前迁移拒绝 activation、equality、mocap 和 plugin 状态。已实现独立的设备附着契约，并用两个惰性模拟适配器检查连接、断开和 Run 生命周期；这不是真机验证。

CPU 直接执行探针已运行 A → A+B → B → 空世界；移除 A 后，B 的 0.5 米动作实测前向偏差约 0.012 米并确认停止，空世界时钟继续。它不是安装候选或独立 Agent 验收。静态关节保持复现了跌倒；零命令步态在短时探针中避免跌倒，但两分钟保持及单机器人空闲试验仍出现缓慢位移，停止确认被撤销。独立 World 进程经真实 ZMQ IPC 总线的 120 秒测试也复现漂移。该历史检查点的安装长期保持尚未合格，技能连续转换资格当时关闭，没有放宽阈值。

新增物理步证据采集与双机器人会合评分器，要求完整数据、至少三秒共同稳定窗口、位移与距离限制、当前停止依据，以及双方各三张独立检查的原始图像。候选 11 构建和安装检查已完成。首次正式试验前的数值现已冻结：共同稳定至少 3 秒、采样缺口不超过 0.1 秒、窗口漂移不超过 4 cm、完整身体外保留 7 cm 余量、楼层高度误差不超过 1 cm、会合距离 1–2.5 m；关节及基座速度标准不变。漂移限值为已测最大安静三秒漂移的两倍并向上取整至 1 cm，楼层容差来自现有足部碰撞球直径且大于实测稳定误差。该历史检查点的正式安装候选三轮会合尚未完成；候选 25 后来完成的全新独立三轮见篇首。前文历史结果仅属于对应旧候选；本节取代旧文中的固定成员和 Brain 随 Run 消失等生命周期描述。


## 候选 11 接入资格结果

候选 11（`f6938d1`）通过 767 项 CPU 测试，跳过两项退役 Provider 检查，并通过前端检查以及干净安装／更新／回滚。两个独立 Codex subagent 通过独立的纯协议 MCP 中继连接安装包，各自在同一个预先存在的 World 申请 G1，并取得持久 Brain。

会合证据同时检查可动物体的当前几何。操作者记录器在每次采样检查全部动态碰撞几何，可仅保存与机器人完整包络加冻结评分余量相交的包围盒；记录完整检查对象集合及余量，缺项或余量不足不能判成功。这降低记录体积，不省略可能侵入所需空间的障碍。冻结的静态障碍约束仍保守适用。
