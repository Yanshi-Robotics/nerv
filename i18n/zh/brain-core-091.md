# NERV 0.9.1 Brain Core 开发说明

[English](../../guides/brain-core-091.md) · [架构](architecture.md) · [MCP](mcp.md) · [控制方案](control-schemes.md)

沿用 0.9.1 版本号，但这是架构与兼容性升级。当前成果是本地开发候选，尚未通过共享世界双 Agent 独立导航验收。

外部 Agent 负责目标理解、视觉判断、规划、模型调用和对话上下文。Brain Core 随 NERV 安装，负责身份绑定、观测回执、任务、授权和执行记录。Runtime 负责驱动、ACT／步态推理、高频控制与本地停止。Brain Core 不包含 AI Agent，也不独立安装。

当前实现位于 `nerv.brain_core`。历史 `nerv.brain`、`nerv.harness`、`nerv.vlm` 源码保留用于恢复，但 wheel 与 npm 包排除其实现。旧聊天、模型、模型密钥写接口返回退役响应；内部上下文压缩写入也已停用。历史记录可读，升级不调用模型、不搬运模型密钥。资源下载凭据另行管理。

每个 Project 仍对应一台受控机器人。操作者先给已配对的客户端分配 Run 和 Brain，固定项目修订及实例身份，再启动和授权。MCP 使用 `nerv mcp --channel CHANNEL --brain BRAIN_ID --client CLIENT_ID`；省略 Brain 只在唯一合法绑定时兼容。新增 `brain_get`，保留原十四个工具的主要用途。回执携带 Brain、Run、Robot、World、绑定与世界代次、可取得的 Runtime／World epoch。重试保留原始执行身份，不按新授权重新标记旧回执。

MCP 桥接登记连接代次并发送存活心跳；心跳不确认图像。第二条连接不能接管同一 Brain。断线或超时撤销该 Brain 的控制，重连只恢复读取，运动必须重新由操作者授权并取得新观测。迟到确认不能恢复旧代次。

共享 World 在启动前冻结机器人组成、出生位置和场景输入修订。源码组合器在一个 MuJoCo model/data 中装配带实例命名空间的机器人树，共用物理时钟与真实碰撞。每台机器人拥有独立总线、Runtime、关节／执行器映射、相机、控制目标和日志。结束 A 的 Run 后，A 停止并留在场景中，B 继续；操作者停止 World 则使全部关联 Run 失效。单 Runtime 进程故障与共享物理进程故障分别失效对应实例和全部实例，恢复不重放动作。

当前共享组合要求同一个注册场景及机器人型号，暂不支持运行中修改拓扑，也不支持非空场景配置覆盖；不支持的请求明确拒绝。

无模型执行服务支持外部原子动作、外部技能和固定策略。新建任务不能抹去同一实例的技能转换历史。Runtime 对 G1 转换另外核对场景及策略、契约、发布文件哈希。本轮开发契约限定已有 G1 转向策略与 apt 仿真，不适用于 Go2、任意策略、ACT 技能转换或真机。

双 G1 并发开发探针共执行 14 次前进／转向动作，14 次确认稳定停止，未报告跌倒。其中六次 0.5 米请求的最终偏差为 0.003～0.021 米，八次 45 度转向偏差为 0.5～3.3 度。这是限定组合的开发证据，不是独立导航验收，也不代表广泛可靠性统计。未验证的 0.5 米以下前进请求在运动前拒绝。接近目标时使用已有策略支持范围内的速度减速，不补偿固定偏移。

动作回执分别报告实测位移、请求目标、目标偏差、受阻、跌倒、超时与停止确认。`travel_threshold_crossed` 表示局部控制阈值；`target_reached=null` 不声称到达目标。最终到达仍须独立评分。Agent 可以静止等待思考，但旧观测失效后必须重新检查图像，不能用心跳或轮询维持运动授权。G1 apt CPU 契约 `g1-apt-cpu-mcp-091-1` 将图像采集至显式确认的有效期设为 40 秒，运动监督期限独立保持 20 秒。两个独立 MCP Agent 的六次看图预检测得采集至确认耗时 11.08–19.96 秒；有效期按实测最大值两倍、向上取整至 5 秒确定，仅适用于 apt 仿真。安装候选的导航与期限故障验证仍待完成。

历史 managed／内部决策项目保留配置和日志，并要求重新选择外部控制方案；不会静默取得新控制权。固定策略保持执行路线。Project／Run／Task 继续是唯一事实记录。候选测试使用隔离数据目录；正式安装替换、公开发布与远程部署分别处理。
