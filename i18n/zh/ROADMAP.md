# NERV 功能路线图

[English](../../ROADMAP.md) · [项目介绍](README.md)

NERV 帮助用户连接机器人、选择控制方案，并查看任务的执行过程。目前开发重点是完善标准 SO-101 的使用流程，明确交互、任务决策与本地执行之间的职责。

本路线图说明后续工作方向，不代表功能已经可用，也不承诺发布日期。优先级会根据测试结果和社区反馈调整。以下扩展均不属于 0.8.2 候选版的实现范围。真机验收和各操作系统的硬件支持单独验证，详见[支持矩阵](README.md#组件更新与支持范围)。

## Harness 配置与扩展

状态：已有内部基础，面向用户的扩展计划中。

内部 Harness 已负责执行循环、上下文、压缩和会话记忆。下一步是完善受支持的配置与诊断入口，说明扩展边界，并验证另一种 Harness 接入。

用户应当能够了解一次执行如何被管理，并在不修改机器人驱动的情况下选择受支持的接入方式。完成标准是提供明确的接口文档和一个实际可用的新增接入，同时保留对话与任务的独立取消、任务记录以及 Host／Runtime 的授权检查。已有接口不等于兼容任意第三方 Agent。

## 插件管理

状态：计划中。

NERV 已有特定的 Provider 与 Runtime 扩展接口，但尚未实现通用插件的安装和管理界面。

后续工作包括插件发现、安装、兼容性检查、权限声明和移除。首个受支持的插件需要走通完整流程，并明确报告依赖缺失或版本不兼容。插件调用机器人动作必须经过现有授权路径，安装插件不能自动获得运动权限。目前不承诺建设插件市场，也不承诺兼容其他应用的插件格式。

## Yanshifu 集成

状态：探索中。

目标是将课程知识、设备使用指导和相关学习工具接入机器人使用流程。NERV 目前不能直接加载 Yanshifu 插件。

下一步先核对可用内容、许可和接口，再基于上述插件边界设计接入方式。完成标准是提供安装说明，并演示一个能够说明知识来源、遵守工具权限的指导流程。接入格式、内容范围和支持版本尚未确定。机器人训练和自动标定仍不属于 NERV 当前范围。

## 如何参与

欢迎通过 [GitHub Issues](https://github.com/Yanshi-Robotics/nerv/issues) 描述需求或提出扩展建议。请说明机器人、操作系统、任务、当前障碍及预期结果。Harness 或插件建议还应包含项目链接、许可证、所需权限和最小可用演示。

请勿提交 API key、私有数据集或能够识别个人的相机录像。路线图条目用于讨论和验证需求，不代表交付日期承诺。开始实现前请阅读[贡献说明](../../CONTRIBUTING.md)。
