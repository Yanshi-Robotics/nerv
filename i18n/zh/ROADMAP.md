# NERV 功能路线图

[English](../../ROADMAP.md) · [项目介绍](README.md)

NERV 面向不同 Agent 提供机器人运行基础，覆盖真实设备和虚拟世界。0.9.1 本地候选版引入 Project 与同机 MCP，保留环境、资产、策略和设备管理。[支持矩阵](README.md#机器人与当前限制) 区分实现、客户端、仿真和真机验收。

下列工作不承诺发布日期。每项说明用户价值、现有基础、下一步及完成证据；在 0.9.1 留出接口，不代表已经交付未来产品。

## Agent 与 Harness 接入

状态：已有本地 MCP 基础，客户端验收与扩展计划中。

用户应能继续使用熟悉的 Agent，而无需替换机器人驱动。Brain Core 提供不依赖模型的身份、观测、授权与执行接口；内部模型循环已经退役。

下一步是测试具体客户端版本、完善配置与可观测性，并验证另一种 Harness 接入。完成需要在实际客户端检查工具发现、图像处理、持续监督、任务与停止、重连行为。协议替身不证明兼容任意第三方客户端。

## 独立本地 Agent 与远程监督

状态：计划中。

独立本地 Agent 项目可以管理模型、上下文与规划，再连接 NERV Brain Core 和 Runtime；Brain Core 随 NERV 安装。现有 MCP 和任务边界提供基础；远程 Agent 还需要带认证的加密传输、设备注册和连接管理。

下一步是验证独立 Agent 部署，以及远程连接与威胁模型。完成需要验证重连不重放动作、预算与停止条件明确、云端或模型失效时本地仍能处理故障。持续在线不证明机器人能够自主完成任务；两个产品均不包含在 0.9.1 中。

## 真实与仿真迁移

状态：探索中。

长期方向包括 Real2Sim、Sim2Real 和多阶段迁移。Project、不可变资产／策略修订，以及独立环境绑定，为可追溯比较提供基础。预留的项目类型目前不运行迁移流程。

下一步选择一个机器人与任务，定义标定和观测对应关系，建立评价标准。完成需要可复现变换、部署契约检查，以及分别记录的仿真与真机结果。场景能加载或动作维度相同，不证明迁移成功。

## 插件管理

状态：计划中。

NERV 已有特定 Provider 和 Runtime 扩展接口，后续希望通过一致流程提供发现、安装、兼容性检查、权限声明和移除。目前没有通用插件市场，也不兼容其他产品的任意插件格式。

下一步验证一个受支持插件的完整生命周期，包括依赖缺失与版本不兼容。完成需要明确的清单和权限边界；插件必须经过 Host／Runtime 动作授权，安装不能自动获得控制权。

## Yanshifu 集成

状态：探索中。

计划把课程知识、配置指导和相关学习工具接入机器人使用流程。NERV 目前不能直接加载 Yanshifu 插件。

下一步检查内容、许可与接口，再确定接入格式。完成需要一个可安装、能标明知识来源并遵守权限的指导流程。内容范围和支持版本尚未确定，训练与自动标定仍不属于当前产品范围。

## 更多机器人与策略

状态：已有适配基础，验证与来源核对持续进行。

SO-101 和 G1 路径提供现有基础。Go2 需要完整、可核验的部署契约后才能开放运动。VLA、WAM 和传统规划仅预留扩展契约，尚未交付通用后端。

下一步取得可复现策略元数据、核对分发权利，并逐个适配器验证停止与监督。完成需要兼容安装方案、明确的观测／动作语义、可重复的仿真检查，以及适用时单独完成的真机验收。多机器人协作留待后续开发。

## 提供使用场景

欢迎通过 [GitHub Issues](https://github.com/Yanshi-Robotics/nerv/issues) 说明机器人、操作系统、任务、当前障碍与预期结果。接入建议请附项目链接、许可、所需权限和最小可用演示，并阅读[贡献说明](../../CONTRIBUTING.md)。

请勿提交 API key、私有数据集或能够识别个人的相机录像。路线图讨论可以改变优先级，但不认证功能，也不承诺交付日期。
